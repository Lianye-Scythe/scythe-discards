# Translation maintenance

The UI follows Chrome's native locale selection. Source dictionaries are `src/i18n/en.json`, `zh_TW.json` and `zh_CN.json`. English is the default fallback. `languageTag` identifies the actual selected catalog, and is used for document language and Intl date/number/unit formatting.

- Add the same message key to all dictionaries. Each value is a plain string.
- `$1` through `$9` are positional parameters. Keep the same parameters in every translation; do not concatenate translated fragments.
- `scripts/build.mjs` converts parameters to Chrome named placeholders and writes `_locales/<locale>/messages.json` with localized manifest metadata.
- `src/i18n/index.ts` provides typed message keys, formatted counts, status labels, errors and activity descriptions. User-controlled titles/hosts remain text in React; no HTML translation injection is used.
- Product naming is centralized in `src/brand.ts`; package/repository naming remains in package metadata.
- Core failures and activities store codes, not localized UI sentences. Browser-provided raw error details cannot be translated by the extension. Old session activity is hydrated into the code representation where possible.

Run `npm test` for key/placeholder consistency, `npm run check` for message-key usage, and `npm run test:locales` for native Chrome locale behavior, long English labels, popup scope operations and narrow layouts.

A language selector is not part of v0.3. Native `chrome.i18n.getMessage` resolves Chrome's language; it is not given an invented per-call locale option.
